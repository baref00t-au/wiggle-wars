# Wiggle Wars

### ▶ Play now: **https://baref00t-au.github.io/wiggle-wars/**

Open it on a phone, tablet, Chromebook, or laptop. On Android (Chrome) or iPad
(Safari) you can **Add to Home Screen** to install it as a full-screen app that
**works offline**.

A browser-based, classroom-friendly multiplayer "growing line" game. Each player
steers a continuously-growing line **left or right only**; you lose if you hit a
wall, another trail, or your own.

Zero install, no accounts, no data collection — see the build plan for the full
design constraints.

**Teachers:** start with the **[brief for teachers](docs/for-teachers.md)**.

## Engaging, not addictive

Wiggle Wars deliberately contains **none** of the manipulative "engagement" patterns
common in kids' games — no random rewards, timers, streaks, social pressure, sticky
exits, or tracking. The rule is: *earn the player's time, don't override their
judgment.* See **[ETHICS.md](ETHICS.md)** for the full checklist and how the game
complies. There's also a classroom lesson,
**[Spot the Trick](docs/lesson-spot-the-trick.md)**, that uses the game as an honest
counter-example to teach kids to recognise these tricks.

## Status

- **Phase 1 — Core simulation:** ✅ done. Pure, deterministic engine in `src/sim`,
  covered by Vitest.
- **Phase 2 — Rendering & single-player test:** ✅ done. Canvas renderer,
  fixed-timestep loop, keyboard input; drive one line with arrows/A-D.
- **Phase 3 — Same-device multiplayer (first shippable):** ✅ done. Menu
  (2–4 players, colours, nicknames, target score, **Human/Bot per slot**),
  keyboard **and** touch input, HUD, round → match loop, death/win effects,
  muted-by-default sound, settings saved locally. **Ready to test with students.**
  - **AI players:** any slot can be a bot (at least 1 human). Bots steer by
    lookahead over a coarse occupancy grid — see `src/ai/`.
- **Phase 4 — Same-WiFi multiplayer:** ✅ done. Host-authoritative netcode over
  WebRTC (PeerJS): a lobby with a room code, one device hosts the authoritative sim
  and broadcasts compact trail deltas, clients render and send only their steering.
  See `src/net/` (the sync protocol is unit-tested in `tests/protocol.test.ts`).

## Architecture rule

`src/sim/` is pure and deterministic: **no DOM, canvas, or network imports.**
The simulation is `step(state, inputs) -> nextState`, a fixed-timestep function of
serializable state. This is what lets every multiplayer mode reuse identical logic.

## Develop

```bash
npm install
npm test            # run the deterministic simulation suite
npm run dev         # Vite dev server
npm run typecheck
npm run build       # production build into dist/ (static files)
npm run generate-icons   # regenerate PWA icons from public/icon.svg
```

## Deploy & install

`npm run build` produces a `dist/` folder of plain static files — host it anywhere
(Netlify, GitHub Pages, a school web folder). It's a **PWA**: on Android (Chrome)
and iPad (Safari) you can **Add to Home Screen** to install it as a full-screen,
**offline** app (Workbox precaches the whole shell; the game makes no network
calls). No app store, accounts, or data collection.

## Android app (Capacitor)

The same build can be packaged as a native Android app that needs **no hosting**:
the web files are bundled inside the APK, so it runs entirely from the device.
(WiFi/Online code games still use the internet for the PeerJS handshake.)

```bash
npm run android:open
```

That runs `build:android` (a Vite build with base path `/` into `dist-android/`),
copies it into `android/` with `cap sync`, and opens the project in Android Studio.
From there: **Build → Build APK(s)** for a sideloadable APK, or **Generate Signed
Bundle** for the Play Store. Requirements: Android Studio with an SDK and JDK 17+.

- `capacitor.config.ts` — app id, name, web folder.
- `vite.config.android.ts` — the base-path/out-dir override on top of `vite.config.ts`.
- `android/` — the native project (committed; `app/src/main/assets/public/` is
  regenerated by `cap sync` and git-ignored). Landscape-only, dark splash.
- `assets/` — launcher icon + splash sources rendered from `public/icon.svg`.
  Regenerate with `node assets/generate-sources.mjs && npx capacitor-assets generate --android`.

## Android app (APK download)

The **Android APK** linked from the home screen is a [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap)
Trusted Web Activity: a thin wrapper that opens the live site full-screen, so it stays in sync with
every deploy. It is published as a GitHub release; the home-screen link always points at the latest:
`https://github.com/baref00t-au/wiggle-wars/releases/latest/download/wiggle-wars.apk`.

- `twa/twa-manifest.json` is the source of truth; `twa/` holds the generated Android project.
- `public/.well-known/assetlinks.json` carries the signing certificate fingerprint. It must match
  the keystore, or Android shows a browser bar inside the app.
- The keystore lives **outside the repo** (`~/.bubblewrap/wiggle-wars.keystore`, password in the
  `.pass` file beside it). Keep it: updates must be signed with the same key.

Rebuild after a site change that alters the manifest, or to bump the version:

```bash
cd twa && npx @bubblewrap/cli update --skipVersionUpgrade
```

Then, from PowerShell (the Gradle daemon can't open its loopback socket from Git Bash here):

```powershell
.\gradlew.bat assembleRelease --no-daemon
```

and sign `app\build\outputs\apk\release\app-release-unsigned.apk` with `zipalign` + `apksigner`
from the Android build-tools. Bump `appVersionCode` in `twa-manifest.json` for every release.
Attach the signed file as `wiggle-wars.apk` to a new GitHub release.

The **Capacitor** project (`android/`, above) is the alternative: a fully self-contained build with
the web files bundled inside the APK, for use without hosting.
